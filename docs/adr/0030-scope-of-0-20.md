# ADR-0030: Release 0.20 is a smaller Luna in a native GPUI window

- **Status:** Accepted
- **Date:** 2026-11-19

## Context

Release 0.19.0 cleaned up the WebView window (idle at 0.0-0.3% of a core),
but the window still costs about 87 MB in its renderer and 325 MB in the
WebView2 GPU process, and its history is one of leaks. Luna has also grown
features that its real use does not carry: in three weeks of logs, no manual
handoff, no account move, no lead rotation, and five automatic handoffs. A
council of two models (Claude Fable, GPT-6-Astra) weighed GPUI against Iced,
egui, Slint, Makepad, Floem, Xilem, Dioxus/Blitz, a custom wgpu stack and
per-platform native UIs; both put GPUI first, on a current pinned snapshot
and conditional on an experiment (`test-build/gpui-spike/`). An audit of
Codex against Claude Code in Luna, and a survey of what both CLIs now offer
natively for helpers and for the library, found work Luna does by hand that
the CLIs do themselves, and security bugs in how Luna reads Codex defaults.

## Decision

One release, 0.20.0, carries all of the following; no release comes between
0.19 and it.

**Window.** The window moves from Tauri + WebView2 + React to GPUI
(`gpui-pre` pinned exactly, with `gpui-component` of the same snapshot). No
JS or TS stays in the repository. The core stays a separate process. Windows
11 is the home platform; macOS is built and tested on GitHub's macOS runners
only, shipped unsigned and marked experimental. Linux is not supported, but
the crate keeps compiling on Linux for the Docker test runs. Screen readers
are not supported (GPUI has no UI Automation). The terminal is our own,
over `alacritty_terminal`; no code from Zed's GPL crates is copied. One
monospace font (Cascadia Mono) for the whole window. The look is retro,
high-contrast and static: no animation, no blinking.

**Cut.**
- Handoff entirely: automatic and manual, account moves, lead rotation,
  their UI, `luna_session_handoff`. The CLIs' own compaction stays.
- Worktree management: Luna creates, inspects and removes no worktree. The
  `worktree` parameter of `luna_session_spawn` goes; a parent wanting
  isolation makes the worktree itself and passes it as `folder`, and Luna
  says so in the tool's description, `luna_guide_get` and the
  luna-orchestrator skill. A chat's worktree box stays, only for folders in
  git, as a flag passed to the CLI.
- Luna's wait-guard hook, on both CLIs.
- The activity sampler: CPU and I/O of processes, output freshness, the
  two-hour leftover hold, screen parsing for status.
- The account recommendations dialog and the recommendations window and
  chip; Applied settings; the account config editor (files open in an
  external editor); the library's "Needs a look" and its diffs; peek by Alt
  and the mouse Back button; chat colors; Even out; drag and drop of chats
  and panes; the F1 window; the Waiting marker; link handling in the
  terminal (a link is text); the attachments store once the window is
  native (dropped or pasted files are typed in as their paths, images go
  through the CLI's own paste key).
- The CLI known-good list, channels, pins and good/bad marks.
- "Codex hooks without asking" (`--dangerously-bypass-hook-trust`) and the
  check that recommends it.

**Kept or simplified.**
- Roles chat / lead / helper, Luna's MCP tools (less the handoff tool), the
  library with its editor, role filters, folder overrides and Luna's own
  system texts. The library is the source of truth: it overwrites what Luna
  manages in an account and leaves foreign files alone.
- Liveness is one record per session from the CLIs' own signals: a turn
  running or waiting for an answer, a shell or cron running, unknown. Claude
  Code: its hooks (status, `Stop` with `session_crons` and
  `background_tasks`) and its `sessions/<pid>.json`. Codex: Luna's status
  hooks (trusted one by one through `hooks.state`), its rollout, and the
  shells in the session's own job. Unknown counts as active.
- Power: keep awake while anything is active; "shut down when all is quiet"
  fires only when no session is active for the whole quiet window, with a
  cancellable countdown. Better not to shut down than to shut down wrongly.
- Peek: a chat not on the board opens full screen over it; "To board" pins
  it; Esc closes it. Boards are five, fixed. The session id copy stays.
- CLI versions: always the newest, a floor raised only by a Luna release,
  automatic rollback when a new version's first sessions fail.
- Settings a CLI needs inside Luna are passed at every launch, never written
  into an account: for Claude `tui: fullscreen` and `copyOnSelect: false`
  through `--settings`, and `CLAUDE_CODE_NO_FLICKER=1`, which outranks the
  CLI's own fullscreen auto-disable; for Codex its update check, its
  notifications and copy-on-select through `-c`. Settings sync between
  accounts stays.

**Codex to parity.** In order: (A) security — unknown or unreadable
approval and sandbox values mean `on-request` + `read-only`, `on-failure` is
`on-request`, `untrusted` and granular tables are passed through `-c`;
settings sync keeps each account's own `hooks.state`; connectors off holds
for project and plugin MCP servers; the Windows sandbox's real guarantees
are verified and documented. (B) status hooks for Codex chats, shells seen
through code mode's results, a helper's usage-limit stop recognized. (C)
Codex helpers and leads run on `codex app-server` (`turn/start`,
`turn/steer`, `turn/interrupt`, approvals and questions routed to the
caller, role text as `developerInstructions`). (D) the instruction size cap,
notices into a chat holding a draft, resume bound to account and thread,
per-account model catalogs, report reading, Authenticode check of the
download.

**Native CLI mechanisms for helpers and the library.** The CLIs' own
interrupt (Claude's `interrupt` control request, Codex's `turn/interrupt`)
instead of killing a turn, falling back to the kill; Claude helpers'
permission prompts over `--permission-prompt-tool=stdio`; Claude folder
skills through a per-session `--plugin-dir` holding only that session's
skills (piloted first); Codex skills hidden by path, not by name; a helper's
result and stderr tail logged on any failed exit.

**Not in git.** Nothing assumes the folder is a git repository: worktree
options appear only in one, and chats, helpers and leads are tested in a
folder without git on both CLIs.

**Fixes.** An update no longer lands the new window on a core of the old
build that still counts a helper's leftover processes as a session:
`stop_all_sessions` ends what helpers' turns left running, and panes wait
for a core rather than fail while it is being replaced.

## Consequences

- The core loses most of handoff (about 15,000 lines of Rust with tests),
  worktree management, the sampler and the power arming machinery; the
  threat model drops the WebView boundary (B1) and is redone through
  `luna-security-review`.
- Until GPUI reaches the agreed surfaces, master has the old WebView window,
  which is not cleaned and may lose functions as the core is cut; nobody
  runs it but the test build.
- GPUI is pre-1.0: the snapshot is pinned, upgraded deliberately, and two
  small patches are carried (runtime shader compilation for release builds
  cross-compiled from Linux; frames on demand instead of a redraw at every
  vsync).
- Codex's `app-server` is experimental in 0.169: every new Codex version
  runs the live suite against it.
- ADRs 0020, 0022, 0023, 0024 and 0027 (handoff and account moves) are
  superseded by this one; ADR-0019 (CLI channels and rollback) is
  superseded in part (channels and marks).
