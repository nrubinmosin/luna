# Luna

*[English version](README.md)*

Тонкая desktop-обёртка (Rust + Tauri) над Claude Code CLI: несколько сессий в панелях,
папки-проекты, аккаунты с изолированными конфигами. Носит с собой собственную копию
бинарника `claude` и сама её обновляет — глобальная установка CLI не нужна.

![Четыре чата в одном окне](docs/screenshots/panes.png)

Подробности по устройству — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Окно

- Оболочка под Windows XP (xp.css, Luna Blue): вместо системной рамки — своя, с
  титлбаром и кнопками свернуть/развернуть/закрыть; шрифт интерфейса Tahoma. Масштаб
  всего интерфейса задаётся одной переменной `--ui` в `src/app/theme.css`.
- Сетка 1/2/3/4 панелей с перетаскиваемыми сплиттерами; чаты затаскиваются в панели из
  сайдбара (⌘/Ctrl+1..4 — раскладка, ⌘/Ctrl+N — новый чат). Панели меняются местами
  перетаскиванием одного титлбара на другой.
- Двойной клик по титлбару панели разворачивает её на всю сетку; двойной клик по строке в
  сайдбаре разворачивает чат вообще без панели. И то и другое — только способ смотреть, а
  не расстановка: доска под ними не меняется, а возврат — повторным двойным кликом (для
  панели ещё и Escape).
- Группы окон I/II/III/IV — вкладки под селектором раскладки. Каждая группа помнит свои
  четыре доски (по одной на раскладку) и их сплиты, у каждой своя кнопка сброса (↺): она
  чистит только расстановку, чаты остаются на месте.
- Темы light/dark/system.

![Тёмная тема, две панели](docs/screenshots/dark.png)

## Чаты

- Новый чат (⌘/Ctrl+N): папка, модель, effort
  (`low/medium/high/xhigh/max/ultracode`), permission mode, аккаунт и чекбокс **Git
  worktree** — включён по умолчанию, сессия тогда стартует как `claude --worktree` в
  `<папка>/.claude/worktrees/<имя>`. Диалог открывается на Opus, high и Bypass; всё это
  потом меняется из самого CLI.
- В титлбаре панели — папка, аккаунт, модель, effort, permission mode, признак worktree и
  сколько контекстного окна уже съедено, плюс кнопки переименовать и удалить чат. На узкой
  панели те же чипы сжимаются.
- Цвета: каждому новому чату достаётся один из десяти пресетов — его носит титлбар панели
  и полоска на строке в сайдбаре, так что связь видна без чтения названий.
- Статус чата — работает / ждёт тебя / отдыхает — читается из собственного реестра сессий
  CLI, поэтому верен независимо от того, открыт чат в панели или нет. Переход в ожидание
  поднимает системное уведомление: окно вполне может быть свёрнуто в трей.
- Расход контекста считается прямо по транскрипту сессии относительно реального окна
  модели (берётся из Models API) — бесплатно и без вранья.
- Заголовок берётся из первого, что набрали в чате, а потом из первой реплики в
  транскрипте. Переименование — двойной клик по имени; заданное руками имя никогда не
  перетирается.
- Метка чата: ★ в начале строки, ставится и снимается кликом. Смысл — какой сам придумаешь,
  приложение её нигде не читает; на непомеченных строках она появляется только под курсором.
- Архив сворачивает чат из списка, не трогая ни сессию, ни worktree, ни транскрипт.
- Картинки и файлы можно вставлять и перетаскивать прямо в панель: они копируются в
  собственное хранилище приложения, а в промпт подставляется абсолютный путь — единственное,
  что в webview остаётся пригодным от буфера обмена.

## Аккаунты

- Аккаунт — это папка `<корень аккаунтов>/<имя>`, по умолчанию `Documents/claude-accounts`;
  ⚙ в панели переносит этот корень куда угодно. «Add» создаёт папку, «✕» удаляет её после
  подтверждения. Сессия чата стартует с `CLAUDE_CONFIG_DIR=<папка аккаунта>` — логин,
  настройки и история у каждого аккаунта свои.
- Живые лимиты (5h / week / model-weekly и время сброса) берутся из OAuth-эндпоинта usage —
  того же, что и `/usage` внутри Claude Code, — то есть не стоят ни одного токена.
  Большинство кругов отвечает кэш самого CLI; при 429 пауза каждый раз удваивается, а не
  долбит эндпоинт с прежней частотой.
- Вход в свежий аккаунт — кнопка на его строке: `claude` запускается в модалке, выходить из
  приложения не нужно.
- Luna сама проставляет CLI-шный признак доверия к папке, когда это нужно: под `--worktree`
  CLI не показывает свой trust-промпт, из-за чего каждую новую папку раньше приходилось
  один раз открывать без изоляции.

## Сессии и уборка

- Закрытие окна прячет приложение в трей, сессии продолжают работать. Выход — через меню трея.
- Сессии, до которых больше не достучаться (чат случайно заархивировали или потеряли при
  недописанном восстановлении состояния), собираются наверху сайдбара — с тем, чем они
  заняты, — и их можно вернуть себе или убить.
- Папке с worktree-каталогами от удалённых чатов предлагается уборка; ничего, в чём сидит
  живая сессия, не сметается. При удалении чата предлагается забрать и его worktree с
  веткой, которую завёл CLI, — по умолчанию они остаются.
- Предупреждения и ошибки обеих половин приложения пишутся в `luna.log`: рядом с exe в
  портативной сборке и в `%LOCALAPPDATA%\luna` иначе. INFO туда не попадает, поэтому всё,
  что в файле есть, стоит читать.

## Разработка

```sh
pnpm install
pnpm dev          # только фронт в браузере (tauri-команды — no-op)
pnpm tauri dev    # полное приложение (нужен Rust-тулчейн)
```

## Скриншоты

```powershell
./screenshots.ps1
```

Перезаписывает `docs/screenshots/*.png` в Docker: поднимается только фронт на выдуманных
чатах и аккаунтах из `src/dev/demo.ts` (`pnpm dev` + `?demo`), снимает headless Chromium.
Снимать живую Luna — значит снимать всё, что в ней открыто; к тому же только фикстура даёт
переснять все три кадра из одного и того же состояния.

## Windows-сборка через Docker

```powershell
./build-windows.ps1
```

Собирает toolchain-образ (rust + cargo-xwin + NSIS + node) и кросс-компилирует под
`x86_64-pc-windows-msvc`:

- портативный exe — `src-tauri\target\x86_64-pc-windows-msvc\release\luna.exe`
  (самодостаточен, нужен только системный WebView2);
- NSIS-инсталлятор — `...\release\bundle\nsis\Luna_*_x64-setup.exe`.

Кэши (node_modules, Windows SDK, cargo registry) живут в named volumes — повторные
сборки быстрые.

## Релизы

```powershell
./release.ps1              # выпустить версию из tauri.conf.json
./release.ps1 -Notes "..." # со своим текстом релиза
./release.ps1 -DryRun      # собрать и составить манифест, ничего не заливая
```

Версия поднимается правкой `src-tauri/tauri.conf.json` и `package.json` вместе; скрипт
откажется работать, если они расходятся, если дерево грязное, если HEAD впереди
`origin/master` или если тег уже есть — релиз обязан воспроизводиться из запушенного
коммита, иначе штамп билда внутри бинаря ничего не стоит.

Скрипт собирает подписанный инсталлятор, пишет `latest.json` для автообновления и
заливает портативный exe, setup, его `.sig` и манифест в релиз `v<версия>`.

## Автообновление и подпись

- Приложение при старте проверяет `latest.json` из GitHub Releases (эндпоинт в
  `src-tauri/tauri.conf.json` → `plugins.updater.endpoints`). Найденный релиз зажигает
  чип в статус-баре и ждёт клика, а не выкидывает модалку поверх того, что идёт в панелях.
- CLI обновляется отдельно и по тому же принципу: `cli.rs` раз в шесть часов ходит в
  release-бакет, сверяет sha256 из манифеста и раскладывает версию в
  `<data>/claude-cli/versions/<ver>/`. Сессии запускаются с `DISABLE_AUTOUPDATER=1`, так
  что этот бинарник двигает только Luna.
- Обе версии живут в настройках (⚙ рядом со списком аккаунтов): там «checked … ago» и
  кнопка проверить сейчас. Статус-бар подаёт голос, только когда есть новость — доступен
  релиз, идёт загрузка или проверка упала и стоит повторить.
- Ключ подписи апдейтов — `C:\Users\Nikita\.ssh\luna-updater.key`: приватный, без пароля,
  береги его; `.pub` уже вшит в конфиг. Для подписанной сборки задай в окружении сборки
  `TAURI_SIGNING_PRIVATE_KEY_PATH` (это и делает `build-windows.ps1`) — тогда рядом с
  бандлом появятся `.sig`-файлы, их и `latest.json` заливаешь в Release.
- Authenticode-подпись exe (чтобы SmartScreen не ругался) требует сертификат: когда будет,
  добавь в `tauri.conf.json` → `bundle.windows.signCommand`.
